# 教学演示提纲：让观众带走一个可复现闭环

## 项目一句话

“这是一套把项目证据变成可追溯长期记忆的 Obsidian 工作流。AI 是可选助手，Markdown、出处、单一入口和恢复能力才是底座。”

不要称为 Obsidian 官方产品、全自动记忆引擎或零成本 AI 服务，不承诺永不遗忘／准确率／节省时长。技术测试与真实业务效果分开。

## 建议演示顺序

1. **从结果开场。** 展示一个虚构项目：同一项下一步从首页、日报、周报都回到唯一出处。提出三个问题：AI 记错怎么追溯？日周撞车怎么办？备份真能恢复吗？
2. **说明问题。** 聊天不是数据库；多份摘要会漂移，收藏不等于掌握，镜像也不是历史版本。
3. **现场打开仓库。** 展示 MIT、目录、快速开始；下载 ZIP，在新文件夹打开 `vault-template`。不要先让观众配置一串插件或购买模型。
4. **做一次资料分流。** 用公开文档，写自己的摘要、来源与“未核实”；展示 captured / promoted 和 evidence_status 的区别。
5. **演示日周月分工。** 一条真实“虚构例子中的变化”进入日报，再在周报解释判断、月报检查长期决定；不伪造生产日报。
6. **演示并发。** 两个隔离 guard 会话，观察同类拒绝／跨类等待；退出并读回事件。录屏前清理终端标题中的私人路径。
7. **演示恢复。** 在虚构示例副本上做镜像、快照和独立恢复；保留额外文件，并展示完整 SHA-256 回执。不要录真实控制回执。
8. **收尾。** 给 GitHub 链接和固定版本；请观众先手动跑通，再接已有 AI／调度器。个人可按需裁剪，不要求整套照搬。

## 可直接用的项目介绍

Obsidian Memory Workflow 是一套免费 MIT 开源的、本地优先的 Obsidian × AI 长期记忆工作流。它提供资料摘录、项目当前状态、日周月复盘与知识卡模板，以及并发保护和备份恢复辅助脚本，帮助把分散沟通整理成有出处、可复查的长期知识。无需社区插件即可开始；AI 和定时调度按需接入，私人知识库不随项目公开。

## 发布前核对

- 录屏只使用虚构示例与新建测试目录；关闭通知、账号页、真实聊天和敏感终端。
- 以实际输出讲“通过了什么”，不要把静态校验说成 Obsidian UI／所有平台／生产效果已验收。
- 分享仓库和固定 release，不附私人笔记、manifest、浏览器导出或原始聊天。
