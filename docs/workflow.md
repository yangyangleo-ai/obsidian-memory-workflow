# 工作流：入口、证据、增量与闭环

## 信息的优先级

用户当前明确决定 → 项目源文件／最新验证证据 → 有效决策 → 唯一当前主笔记 → 日志／聊天摘要。摘要不拥有覆盖源证据的权力；冲突并列保留，注明再核实条件。

## 一个事实，一个主位置

项目入口只路由到主笔记和源路径。主笔记记当前结论；日报记变化；周报解释判断；月报复查长期决定；知识卡记跨场景可复用的方法。不要让这五种文档各自重复维护“最新真相”。

## 增量不等于今天修改的文件

每来源使用 `(last_scanned_until, scan_until]`，另用内容哈希／消息 ID 去重。文件时间只作为候选信号；保留旧时间的新增文件靠路径清单变化发现。首次建立清单是基线，不把所有历史资产写成今天成果。

`started_at` 是实际启动；`scan_until` 在取得作业门、重读最新状态后固定；`completed_at` 只说明什么时候结束。不能拿完成时间作下轮扫描起点。延迟运行保留实际时间，不补造关机期间的多篇报告。

## 状态分开

| 字段 | 例子 | 不能证明什么 |
| --- | --- | --- |
| coverage_status | NOT_ASSESSED / PARTIAL / COMPLETE | COMPLETE 也不证明所有来源内容正确 |
| write_status | DRAFT / COMMITTED / NO_CHANGE / FAILED | 写完不等于镜像成功 |
| mirror_status | NOT_CHECKED / VERIFIED / FAILED | 哈希一致不等于业务已验收 |
| restore_status | NOT_CHECKED / VERIFIED / FAILED | 一个文件恢复不等于完整快照可恢复 |

周期复盘可对已验证的部分做判断，其他范围保留；只有本任务已核验的输入指纹能推进，不能顺手改其他任务游标。

## 先排队，再读，再写

同类 job guard 防重入，全局 job guard 让日／周／月／手动维护串行；取得后重新读状态。写入另外取得 write guard。逐文件备份、读取时哈希、写前再比较仍必需。超时／忙记 DEFERRED_LOCK，不删锁、不推游标。

## 不默认自动化的事

不自动开发项目、不恢复暂停任务、不补研究材料、不发消息／发布、不交易／付款、不删除旧证据、不安装扩展或连接新模型。任务执行与知识整理是两种职责。
