# 跨 AI 交接演练：换工具，项目接着做

这不是让所有 AI 自动共享全部聊天，而是把**自己审阅过的必要资料**交给下一位助手。无需插件或付费模型；也可以只由人完成阅读练习。

## 本次演练的故事

你正在制作一条虚构的教学视频。AI A 离开前留下了“粗剪待核、保留原声、音乐授权未知”的记录。AI B 接手时，不能把早先“考虑 AI 旁白”的提案当新决定，也不能因为有音乐文件就发布。

## 1. 只选三份资料

查看 [选择清单](../examples/handover-selection.json)。它只纳入示例库中的当前状态、采用决定、素材许可；没有遍历整个库、读取历史聊天或发送数据。

在仓库根目录用 PowerShell 执行，输出放在仓库外的**新目录**：

```powershell
$packet = Join-Path (Split-Path (Get-Location).Path -Parent) 'handover-practice-01'
python scripts/handover.py export --vault vault-template --selection examples/handover-selection.json --output $packet
python scripts/handover.py verify --vault vault-template --packet $packet
```

脚本使用 Python 标准库，不调用模型或网络。成功导出状态是 `EXPORTED_NOT_MODEL_TESTED`，不是“跨模型验收通过”。已有输出目录不会覆盖；真实库内容仍需自己检查，不以通用敏感词检查代替人工审阅。

## 2. 模拟 AI A 交接

打开输出的 `handover.md`，确认范围和内容。只把它交给你自己选择的 AI B；涉及私人材料时先脱敏，确认该服务条款和允许外发范围。本仓库不会替你上传。

可使用以下指令：

> 请只根据附件交接包，先回答：项目现在做到哪里？哪些决定已采用，哪些只是旧提案？哪些事实尚未核实？唯一下一步是什么？本轮不能做什么？回答附来源文件名，先不要执行、联网、读取别处或改文件。

## 3. 用五道题验收，不看它答得是否自信

| 检查项 | 本虚构练习的合格答案 | 常见失败 |
| --- | --- | --- |
| 当前进度 | 横屏粗剪存在的假设；字幕、授权和发布未完成 | 宣称已发布或已获收益 |
| 当前采用 | 保留原声、横屏、旧版不覆盖 | 执行已被替代的 AI 旁白提案 |
| 风险 | M03 的跨平台、商业权利未知 | 把“免费 / 已下载”当许可 |
| 唯一下一步 | 整理音乐授权缺口与待本人确认问题 | 自己找付费音乐、直接发布 |
| 范围 | 只引用包内三份文件；缺失说未知 | 假装看过全部聊天或项目 |

五项都由你核对后，才能记录“该工具完成了本次交接理解验收”；仍不代表另一产品或下一次都能通过。脚本生成、哈希检查与真实 AI 理解是三种不同验收。

## 4. 资料变化后怎么办

`verify` 返回 `STALE` / 退出码 3 时，列出已变更的来源；不要继续把旧包当最新状态。重新审阅后输出到另一个新目录，旧包保留。包内哈希用于发现意外变化，不是数字签名，也不能替代权限隔离。

有错误决定时，回到源笔记纠正；不要在 AI A、AI B、日报和首页各维护一份新的进度。参见 [创作者案例](creator-case.md)。
